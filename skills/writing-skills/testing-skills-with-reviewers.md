# 用代表任务评测 Skill

在需要判断指导是否改变实际行为时使用；格式、链接和 schema 问题用静态检查。

## 设计一个有辨别力的场景

先写下可观察的成功条件和失败条件，使用真实任务形状与必要原始材料。给 evaluator 用户请求、skill 和原始产物，不泄露预期答案或作者的修复结论。Evaluator 只返回任务响应或隔离产物，不修改 skill 或生产状态。

已有真实失败产物或明确规则冲突可以作为修改前证据。要证明 skill 相比无指导的增量效果时，使用相同输入分别测试无 skill 对照和候选；对照也成功时，不宣称候选带来了改善。

默认从一个代表场景开始。多场景评测先设调用预算；只有出现新失败、歧义或已观察的方差才增加样本，并说明它会改变哪个决定。不要展开完整组合矩阵或重复采样直到得到期待答案。

## 判断与复查

保留输入、skill 版本、原始响应和判断依据。检查实际交付物与动作，不把规则复述、模型自评或声称会遵守当成行为证明。

候选失败时先区分规则问题、场景歧义、加载失败或判定不足，只修观察到的问题，再测受影响场景。结果不可区分时明确说证据不足，不通过重复抽样制造结论。

通过只表示该场景满足条件，不证明所有任务或模型都有效。跨 skill 修改还要检查流程衔接，由独立只读 reviewer 审查并定点复查必要修正。
