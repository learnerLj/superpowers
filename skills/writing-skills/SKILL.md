# 编写 Skills

默认 agent 已具备通用能力。只补充会改变其决策的领域知识、项目外可复用的方法、真实边界和工具用法；项目专属规则留在项目 owner，机械限制优先用工具执行。

## 编写

先读现有入口与相关资源，确认具体缺口：真实使用问题、重复或冲突规则、失效引用，或用户明确要求改变的行为。保留授权范围，不因一次失败追加普遍禁令。

一个 skill 拥有一个清楚的用途。description 简短说明何时触发；正文保留核心流程与必要边界，专项资料在需要时链接。删除重复教学、口号和无依据的例外，不把删掉的全文换个位置再要求全部读取。

## 验证与审查

- 检查名称、frontmatter、引用、调用策略与入口和模板的一致性，使用目标宿主的 validator。
- 修改工具或脚本时检查真实输入输出及副作用；涉及外部依赖或执行权限时审查相应资源。纯文字修改不重跑无关脚本测试。
- 行为变化用一个有代表性的任务做独立检查；真实旧产物或规则冲突可作修改前证据。需要证明 skill 的增量效果时才做无 skill 对照。
- 跨 skill 流程修改由一个独立只读 reviewer 检查流程衔接和遗漏，修复后定点复查；通过后进入最终验证。

行为样例只能证明覆盖的场景，不能凭模型自评宣称普遍有效。有新失败或歧义才增加评测，不为防范假想问题展开矩阵。

需要设计行为对照时读取 [testing-skills-with-reviewers.md](testing-skills-with-reviewers.md)；涉及格式或宿主差异时读取 [anthropic-best-practices.md](anthropic-best-practices.md)，其中外部事实按需核对当前文档。
