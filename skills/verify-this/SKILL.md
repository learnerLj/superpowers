# 验证具体声明

先确定要证明的事实、范围和通过条件，再从真正拥有该事实的来源取证。默认只验证；用户同时要求修复时，记录结论后继续处理。

- **当前状态**：直接检查 runtime、远端、数据库、配置或实际消费方。
- **因果与比较**：使用可比的输入、环境和测量方式做前后对照；缺少基线或有明显混杂因素时不作确定归因。
- **任务完成**：对照用户要求、实际产物、必要审查和外部状态，不以计划、文件存在或本地测试代替整体验收。

选能直接推翻声明的最小验证面，遵守任务权限和资源限制。需要实时状态就取当前证据；稳定事实的已有证据仍然适用时可复用，明确其来源与时效。不为获得结论擅自写入生产系统。

给出明确判定：`VERIFIED` 表示证据支持，`NOT VERIFIED` 表示观察与声明冲突，`INCONCLUSIVE` 表示证据不足或不可比较。附关键依据和覆盖边界，不强制字段模板，不重复取样直到出现期待答案。

本 skill 处理用户主动提出的核实任务；`verification-before-completion` 负责交付前验收。两者使用相同有效证据时无需重复取证。
