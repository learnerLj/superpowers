# 验证具体声明

把用户提出的说法改写成可证伪声明，从拥有该事实的 authority 获取新鲜证据，并给出明确判定。验证的目标是证明或推翻一个具体声明，不是复述已经做过什么。

## 职责边界

- 本 skill 由用户明确要求验证、证明、核实或展示依据时触发。
- `verification-before-completion` 是 agent 准备声明任务完成时必须执行的自动门槛；本 skill 是用户主动提出怀疑后，对指定声明进行独立验证。两者可以先后使用，但不互相替代。
- 默认只取证和判断，不顺手修复问题。用户同时要求修复时，先完成并记录验证结论，再按适用开发流程实施。
- 验证需要修改生产状态、写入外部系统或执行其它高风险动作时，改用可证明同一事实的只读观察；不存在安全观察面时说明阻塞，不为获得结论擅自制造状态。

## 验证流程

1. **明确声明**：根据上下文写出条件、范围和通过条件。只有多个解释会改变取证方向时才询问用户，不把可自行明确的问题退回给用户定义。
2. **找到事实 authority**：确认谁真正拥有这个事实，例如 Git remote、当前 working tree、runtime、数据库、服务 API、浏览器行为、部署平台、原始产物或一手来源。
3. **选择验证模型**：按声明类型选择直接观察、前后对照或逐项验收，不强迫所有问题使用同一种模板。
4. **选择最小权威验证面**：优先选择能够直接推翻声明的最小 surface；局部测试不能证明用户可见行为时，继续检查真实消费方或端到端结果。
5. **执行新鲜取证**：现在运行命令或读取状态，保留足以复查的命令、来源、关键原始结果、退出码、时间和相关环境。不能用旧输出、他人结论或记忆代替。
6. **对照通过条件**：检查失败、警告、跳过项、覆盖边界和混杂因素。证据只覆盖一部分时缩小声明，不能从局部成功推出整体成功。
7. **给出判定**：每个独立声明返回 `VERIFIED`、`NOT VERIFIED` 或 `INCONCLUSIVE`。只有预先定义了聚合条件时，才给多个声明生成一个总体 verdict。

## 按声明类型取证

### 状态型声明

用于“是否已经 push”“服务是否健康”“配置是否生效”“当前仓库是否干净”等问题。直接比较通过条件与当前 authority 的观察结果，不要求人为制造旧状态或 treatment。

### 因果或比较型声明

用于“这次修复消除了故障”“性能提高了 20%”“内存下降了”等问题。使用相同命令、输入、数据、warmup、环境和测量方法比较 `baseline` 与 `treatment`；无法得到可比基线或存在明显混杂因素时返回 `INCONCLUSIVE`。

### 完成型声明

用于“任务是否真的完成”“交付是否落盘”“迁移是否结束”等问题。逐项对照验收条件、真实产物、消费方和外部状态。计划、描述或文件存在只证明意图或产物存在，不证明行为、语义、部署或迁移已经完成。

### 事实型声明

用于“这个依赖是否仍在使用”“某项数据是否来自指定来源”等问题。读取最接近事实 owner 的代码路径、运行状态、原始数据或一手来源，并明确推断和未知项。

## Verdict 规则

- `VERIFIED`：新鲜证据满足该声明自己的通过条件，覆盖范围足够，且没有会推翻结论的已知混杂因素。
- `NOT VERIFIED`：观察结果与声明冲突、没有达到阈值，或真实状态证明该声明不成立。
- `INCONCLUSIVE`：authority 不可访问、证据不足、验证面不匹配、测量噪声过大，或环境差异使结果无法比较。

负面结果不需要软化。证据不足时不能把 `INCONCLUSIVE` 写成“基本验证通过”，也不能反复取样直到得到期望答案。

## 证据纪律

- 测试通过只证明测试实际覆盖的 contract，不自动证明 UI、生产状态或完整任务。
- 本地 commit 不证明已经 push；部署命令成功不证明服务健康；API 返回成功不证明最终消费方正确。
- reviewer、subagent、日志摘要和先前对话可以提供线索，不能替代当前 authority 的直接证据。
- 验证后事实发生变化时，受影响的证据立即失效，必须重新取证。
- 默认在回答中保留最小必要证据。只有性能 profile、多轮实验、截图比较或需要复查的大型产物才写入临时目录，并先避免 secrets、个人数据和敏感响应落盘。

## 输出

按声明复杂度裁剪，但必须包含 verdict、声明、通过条件、事实 authority、关键证据和证据边界：

```text
VERIFIED | NOT VERIFIED | INCONCLUSIVE
声明：<可证伪声明>
通过条件：<什么观察结果会使声明成立>
事实 authority：<拥有该事实的来源>
证据：<命令或观察、关键原始结果、必要的 baseline/treatment 对照>
判断：<证据为什么满足或不满足通过条件>
边界：<未覆盖范围或混杂因素；没有则写“无已知关键缺口”>
```
