# 开发与测试流程

围绕目标行为建立测试保护，用反馈推进实现。采用测试先行的思路，具体方法和粒度按任务判断。

1. **明确行为**：确认需求、现有消费路径和完成条件，选择能发现目标错误的测试。
2. **先验证缺口**：新增行为或 bugfix 优先用失败测试表达预期；纯重构先确认现有行为有测试保护。
3. **实现并验证**：完成满足需求的修改，运行相关测试，依据失败结果修正实现。
4. **整理与复验**：在行为正确的基础上简化代码，只重验受影响部分。
5. **审查与交付**：重大或高风险变更进入 `requesting-code-review`，核查反馈、修复并复查；最后按 `verification-before-completion` 验收。

已有实现不为重演顺序删除，仍有效的验证证据可以复用。测试范围与资源限制以项目约定为准；测试通过只证明实际覆盖的行为。

本 skill 仅在明确要求时调用，不作为普通开发的自动约束。遇到具体测试质量问题时，可参考 [writing-good-tests.md](writing-good-tests.md)。
