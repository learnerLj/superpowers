# 编写有效测试

遇到期望值镜像实现、mock 隐藏真实行为，或测试难以发现破坏时读取。

## 独立推导预期

先说清测试能捕获的具体错误：错误分支、缺失副作用、参数错误或边界条件。期望值来自需求和人工核对的 fixture，不用被测代码或同一个 helper 计算答案。

```python
# 无法发现 builder 自身的错误
assert build_query("urgent") == build_query("urgent")

# 验证明确的输出 contract
assert build_query("urgent") == 'tag:"urgent"'
```

内部常量、私有结构或文案只有属于实际 contract 时才直接断言；否则检查依赖它的消费行为。不要重复测试框架已有能力，或为简单 getter、转发方法单独堆测试。

## 保留真实目标

只替换需要控制的边界，例如网络、时钟、随机源或昂贵依赖。了解被替换方法的副作用，避免 mock 吞掉本应验证的校验或状态变化。

断言被测组件的输出、状态和外部交互。参数、调用次数或顺序属于承诺时，spy/fake 断言有价值；仅证明 mock 按设置返回了值则没有价值。Fixture 要覆盖本测试依赖的真实协议结构，避免因缺失字段制造与生产无关的结果。

Mock setup 膨胀时，考虑使用真实组件或更靠外层的测试边界。测试专用 helper 放在测试代码中，不给生产结构增加只为测试服务的接口。

## 确认测试有辨别力

问一个具体反例：如果改错分支、遗漏状态更新或传错参数，这个测试会失败吗？必要时在隔离副本中验证，不破坏共享工作树或生产状态。

行为 bug 优先用失败回归测试证明。已有实现不为重演 TDD 顺序删除；已有有效证据不为完成仪式重复运行。没有实际运行就不声称测试通过。

脚本和程序以输出、副作用或退出状态验证；agent 指导的行为改变用代表任务检查实际响应。格式、链接、schema 用静态检查即可，不把逐字匹配规则文本当成行为证明。
