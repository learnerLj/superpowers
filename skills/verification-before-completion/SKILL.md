# 完成声明与证据

先明确用户要的结果，再用能直接观察它的证据检查。文件存在、命令退出成功、reviewer 说通过，都不能自动证明整个目标完成。

## 选择相称的检查

- **代码**：检查任务范围内的最终修改，使用直接覆盖改变行为的测试或检查；不把无关 dirty 文件、合入内容或 staged 列表变成测试范围。
- **文档与配置**：检查内容、引用、格式，以及适用的实际消费结果。
- **研究**：核对来源、时间、覆盖边界，区分事实、推断和未知。
- **部署与外部状态**：从目标系统读回状态或检查实际消费方，不能以本地构建成功代替。

已有证据只要仍对应当前实现、输入和环境就可复用；不要求为了最后一条消息再跑一遍。变动会影响证据，或时效本身属于要求时，才重验受影响部分。运行范围和成本遵循用户与项目限制，不默认追加 build、lint 或全量测试。

## 结束工作

对照用户要求，以及存在时的计划，确认已授权的工作、必要 spec 审查、实现审查和修复复查均已完成；遗漏继续处理。仍有必要审查在运行时先取得结果，不把未结束工作说成完成。

简要报告交付内容、实际检查和重要未验证范围。部分成功只描述已证明的部分；受阻时说明缺失条件。不要强制输出完成等级、验证矩阵或不适用的检查清单。
